On a failed background refresh, the existing list/count failure policy applies:
the confirmed-inaccessible item stays removed and the last known count is kept
until a successful refresh. No read-all write or invented count is used to clear
the badge. These browser journeys use mocked Auth and API responses, not shared
database fixtures or hosted authorization/concurrency verification.
