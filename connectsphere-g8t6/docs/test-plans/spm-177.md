# SPM-177 assignment review fixes

Prepared on `fix/SPM-177-review-findings` from frontend PR #3 head
`c0ac289278c5f12c340654858a7992f95f8fdfa8`. Conflict resolution integrates frontend main
`c90d5dfb67a23bd20fa131b2fa25e68828127b71`.

The queue remains on `/events` for Coordinator Leads; Attendees retain their
existing discovery view. Regular Coordinators are denied the queue and cannot
navigate to it through their role menu or login-return URL. The feature lives
under `components/coordinator-lead/` and uses the established shared workspace,
trusted profile, Supabase client and `apiRequest` session-expiry handling.
The redundant AuthProvider and unused backup are removed. Main's working
SPM-180 assignments page, supervision fields, API contracts, navigation, Lead
login destination and shared styling are retained. Queue cards retain purpose,
venue/equipment requirements and submission time.

Assignment still requires explicit confirmation. Pending requests are guarded,
success feedback follows the backend response, and stale/uncertain outcomes
require a fresh read before another write. Retry restores a failed queue load;
a schedule outage preserves the queue while disabling assignment.

Calendar days and labels use Singapore time, independently of browser timezone.
Overnight events occupy each overlapping day; an exact midnight end does not
occupy the next day. Shorter-month navigation clamps the date. All/None filters
set the requested selection instead of inverting a mixed selection.
