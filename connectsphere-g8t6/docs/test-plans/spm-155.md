# SPM-155 frontend test plan — attendee notifications

Story [SPM-155](https://yvery.atlassian.net/browse/SPM-155), subtask SPM-161
(Notifications page), on `feature/SPM-155-attendee-notifications`. The backend
contract and database coverage are in the backend repository's
`docs/test-plans/spm-155.md`.

## Design reference

| Frame | Used for | URL |
| --- | --- | --- |
| `282:664` My Events | Updates button with unread count in the page header | `/my-registrations`, `/events` |
| `282:1173` Notification card | Updates panel; row design reused on the full inbox | panel; `/notifications` |
| `282:1271` Event details modal | Shared event details dialog (Event Discovery, My Events, Go to Event). My Events and notification links keep this dialog; SPM-44 additionally supports direct attendee `/events/<id>` URLs through discovery | `/events`, `/my-registrations?eventId=<id>[&from=notification]` |

Not built from the frames: search, filters, photos, Withdraw, Accept/Decline
Slot (SPM-163) and "Live Updates Active" (Master 8 promises no instant
delivery). Inter is replaced by Hanken Grotesk and frame colours are mapped to
the nearest tokens.

## Coverage

| Criterion | Automated evidence |
| --- | --- |
| AC3 offer expiry | Unit: `offerExpiry`. E2E: expiry and expired wording on the inbox and in the panel. |
| AC4, AC5 / TC-05, TC-06 | Unit: `notificationTargetHref` (adds `from=notification`). E2E: Go to Event marks read and opens the event details dialog on My Events, read from `GET /api/registrations/mine/:eventId` and never from Event Discovery (latest details in SGT, your place, no sign-up action), with the card outlined and labelled "Opened from your notification" behind it and focus returned on close; View Event Details on a card opens the same dialog without the label, and the dialog has no link to a separate page; a cancelled event that had been confirmed shows its last confirmed details under "These are its details as last confirmed on …"; a never-confirmed cancelled event shows title, status and "Its date, time and venue are no longer shown." only; an event being reconfirmed shows its last confirmed details under "These are the details last confirmed on …" when it had a confirmation, and otherwise, like an unpublished one, says only "This event's details are being confirmed"; neither notice mentions notifications or organisers; a waitlisted place reads "On the waitlist", never "Waitlisted"; an event the attendee can no longer see shows "no longer available".
